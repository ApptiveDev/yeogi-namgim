# 회원 보관함 API

관련 이슈: [#94](https://github.com/ApptiveDev/yeogi-namgim/issues/94). 모든 경로는 회원 Access Token이 필요하다. 인증·응답 형식은 [공통 API 계약](BACKEND_API_CONTRACT.md), 저장 동작과 공개 범위는 [저장 API](BOOKMARK_API.md)를 따른다.

`GET /api/v1/users/me/archive/calendar?month=2026-11`은 월별 날짜와 작성·저장 수를 반환한다. 응답 데이터는 `month`, `days: [{date, writtenCount, savedCount}]`다. 날짜는 저장 시각이 아닌 **쪽지 원본 `createdAt`을 `Asia/Seoul`로 변환**해 정한다. 기록이 없는 날짜는 제외한다. 작성 기록과 현재 볼 수 있는 저장 기록을 별도로 센다.

`GET /api/v1/users/me/archive/notes?date=2026-11-02&type=ALL&size=20`은 해당 날짜의 쪽지를 `createdAt DESC, noteId DESC`로 반환한다. `type`은 `ALL/WRITTEN/SAVED`, 기본값은 `ALL`이다. `WRITTEN`에는 `writtenVisibility=ALL/PUBLIC/FRIENDS/PRIVATE`, `SAVED`에는 `savedCategory=ALL/FRIEND/ANONYMOUS`를 사용할 수 있다. `ALL`이나 다른 유형에 맞지 않는 하위 필터를 보내면 `400 INVALID_REQUEST`다. 기본 크기는 20, 허용 범위는 1~100이다.

목록 응답에는 `notes`, `size`, `hasNext`, `nextCursor`가 있다. 첫 요청에서는 `cursor`를 생략한다. `hasNext=true`이면 `nextCursor`를 그대로 다음 요청의 `cursor`에 넣고 **같은 날짜·유형·하위 필터**를 유지한다. 예: `GET /api/v1/users/me/archive/notes?date=2026-11-02&type=ALL&size=20&cursor=<nextCursor>`. 마지막 페이지는 `hasNext=false`, `nextCursor=null`이다. 커서는 회원·날짜·필터에 묶인 불투명 값이며 다른 조건에서 재사용하거나 잘못된 값을 보내면 `400 INVALID_REQUEST`다. 기존 `page` 파라미터도 `400`으로 거절한다. 정렬 기준이 같은 쪽지는 쪽지 ID 내림차순으로 이어서 조회한다. 새 쪽지가 앞에 추가되어도 이미 받은 커서 뒤의 결과가 밀리지 않는다. 저장 취소·공개 범위·친구 관계 변경은 조회 시점에 다시 적용하므로, 그 사이 볼 수 없게 된 쪽지는 다음 페이지에서 제외된다.

저장 분류의 `FRIEND/ANONYMOUS`는 **조회 시점의 현재 친구 관계**로 계산한다. 친구 해제 후 공개 쪽지는 `ANONYMOUS`로 분류되고 더 이상 볼 수 없는 `FRIENDS` 쪽지는 목록과 달력에서 빠진다. 내가 쓴 쪽지는 저장 기록 없이 `WRITTEN`에 포함된다. 보관함 목록 조회는 읽음 기록을 만들지 않는다.

보관함 카드의 `authorCategory`는 `MINE/FRIEND/ANONYMOUS`다. `authorDisplayName`은 내 쪽지에는 현재 내 닉네임, 현재 친구의 저장 쪽지에는 그 친구의 닉네임, 그 외 저장 쪽지에는 `익명`을 반환한다. 친구 관계가 바뀌면 다음 조회부터 표시명도 다시 판정한다. 보관함 응답에 작성자 회원 ID는 포함하지 않는다. 이 표시명은 보관함 목록에만 추가되며 저장·발견 목록의 응답 계약은 유지한다.

## 프론트 보관함 연동 — 이슈 #131

- 보관함 목업 데이터와 개발자 설정 의존성은 제거했다. 전체·저장·내 노트는 실제 회원 API를 사용한다. 친구 노트는 후속 연동 대상이며, 예시 데이터나 준비 중 표시 없이 기존 빈 상태를 표시한다. 미연동인 친구 건수는 `—`로 표시한다.
- `type=ALL`로 받은 목록 하나를 공유한다. 전체는 작성·저장 모두, 저장은 `isSaved=true`, 내 노트는 `authorCategory=MINE`인 쪽지를 화면에서 필터링한다. 필터 변경은 별도 API 요청·목록 초기화·필터 컴포넌트 재생성을 일으키지 않는다.
- 월별 배지의 전체·저장·내 노트 건수는 같은 달력 응답의 `writtenCount/savedCount`를 합산한다. 일부 페이지만 받은 목록의 길이를 전체 건수로 사용하지 않는다. 필터·날짜를 바꿔도 월별 건수를 유지한다. 조회 전의 미확인 건수는 `—`, 실제 빈 달은 `0`으로 표시한다.
- 날짜 미선택 시 달력에 기록된 날짜를 최신순으로 이어 조회한다. 최초 조회와 `더 보기`는 최대 20개씩 가져오고, 각 날짜의 서버 커서를 유지한다. 재진입 검증은 이미 표시한 분량을 처음부터 다시 조회하며 개별 API 요청의 `size`는 100을 넘지 않는다. 날짜 선택 시에는 그 날짜의 `ALL` 목록을 조회하며, 기록이 없는 날짜도 조회할 수 있다. 다음 페이지는 `더 보기`로 가져오며, 이미 받은 쪽지에 현재 필터를 적용한다. 필터에 맞는 쪽지가 아직 없어도 다음 페이지가 남아 있으면 빈 보관함으로 확정하지 않는다.
- API 날짜·오늘 표시·카드 작성일은 `Asia/Seoul` 기준이다. 카드에는 서버 작성자 표시명·미리보기·장소를 표시하며, 열람 가능한 실제 카드만 상세 화면으로 이동한다. 본인·저장 쪽지 상세는 위치 없이 열고 기존 열람 API에서 현재 공개 권한을 다시 검사한다. 저장 취소 후 같은 상세에서 다시 저장할 때는 기기의 현재 좌표를 보내 서버에서 150m 거리 조건을 확인한다.
- 로그인별 메모리 캐시는 화면을 떠나도 유지한다. 보관함이 다시 포커스를 얻을 때마다 현재 월의 달력과 표시 중인 목록을 백그라운드에서 재검증한다. 노트를 작성하거나 저장 상태를 바꾼 뒤 돌아오면 이 조회 결과로 반영한다. 캐시가 있으면 재진입 시 로딩 표시로 전환하거나 기존 목록·건수를 비우지 않는다. 필터 변경·백그라운드 복귀·저장 변경 이벤트 자체는 추가 요청을 만들지 않는다. 처음 선택한 월·날짜와 `더 보기`는 필요한 미조회 데이터를 가져온다. 앱 종료 시 캐시는 사라지며 목록·미리보기를 기기 저장소에 영구 보관하지 않는다.
- 새 응답의 날짜별 건수·쪽지 ID와 순서·카드 표시 필드·접근 상태·다음 커서를 비교한다. 값이 같으면 기존 배열·카드·달력·스냅샷 참조를 유지하고 변경 알림도 보내지 않는다. 값이 다르면 변경된 값만 교체한다. 여러 페이지를 펼친 상태에서도 재진입 시 표시 분량을 유지하며 커서를 새 목록에 맞춘다.
- 당겨서 새로고침은 기존 값을 유지한 채 새로고침 표시를 제공한다. 오류는 재시도를 제공하며 재진입 검증이나 후속 페이지 실패 시 기존 목록과 커서를 유지한다. 이전 로그인·무효화된 요청의 응답은 현재 보관함에 반영하지 않는다. 회원 요청은 공통 세션의 토큰 재발급 흐름을 사용한다.

프론트 자동 검사는 `npm run test:archive`, `npm run test:auth`, `npm run test:member`, `npm run lint`, `npx tsc --noEmit`로 실행한다. 보관함 테스트는 실제 API 클라이언트·세션·캐시·페이지 조회 코드를 사용하고 HTTP 및 기기 보안 저장소를 대체한다. 재저장 테스트는 위치 API를 대체해 상세 열기·저장 취소·재저장 요청의 위치 전달을 검증한다. 실제 기기의 필터 애니메이션·당겨서 새로고침·위치 권한·운영 API 연동은 별도 확인 대상이다.
