# 3차 세미나 백엔드 개발 현황과 계획

- 기준 기획: 2026-11-15 회의 결정 및 3차 프로토타입 v12
- 코드 확인: 2026-11-17 `main`의 `5ea1c8f`
- 관련 이슈: [#144](https://github.com/ApptiveDev/yeogi-namgim/issues/144)

이 문서는 3차 세미나 개발 안내를 최신 `main`의 컨트롤러·서비스·Flyway 마이그레이션과 대조한 결과다. 기존 2차 문서와 충돌하면 이 문서의 확정 정책을 우선한다. `[완료]`는 `main`에 병합된 백엔드 구현, `[일부]`는 기반 API는 있으나 3차 완료 기준과 차이가 있는 상태, `[미구현]`은 새 백엔드 작업이 필요한 상태다.

## 1. 지도 정책 변경

현재 `ALL`은 내 쪽지, 타인의 `PUBLIC`, 현재 친구의 `FRIENDS`를 함께 반환한다. 3차의 공개 지도는 `PUBLIC`만, 친구 지도는 현재 친구와 내가 작성한 `FRIENDS`만 보여야 하므로 현재 계약을 그대로 사용할 수 없다.

- 기존 클라이언트 호환을 위해 `ALL`의 의미를 바로 바꾸지 않는다.
- `NoteMapFilter`에 공개 지도 전용 값 `PUBLIC`을 추가한다.
- `PUBLIC`: 작성자와 관계없이 회원 `PUBLIC`만 포함한다.
- `FRIENDS`: 현재 친구의 `FRIENDS`와 내 `FRIENDS`를 포함한다. 친구의 `PUBLIC`, 모든 `PRIVATE`는 제외한다.
- 같은 필터 조건을 일반 지도와 클러스터 쿼리에 적용한다.
- 모든 응답은 기존처럼 현재 회원 기준 `isMine`을 제공한다.

## 2. 읽음·저장·150m와 묶음 상태

개별 마커의 읽음·저장 상태와 열람 가능 여부는 이미 실제 데이터 소스에 연결되어 있다. 상세 열람 성공 시 읽음 기록을 저장하며, 본인 및 현재 접근 가능한 저장 쪽지는 거리 예외, 타인의 미저장 쪽지는 150m 이하에서만 열람한다.

묶음 API에는 현재 `count`만 있으므로 다음 필드를 추가한다.

```json
{
  "clusterId": "4:4",
  "count": 8,
  "unreadCount": 3
}
```

- `note_discoveries`를 현재 회원 기준으로 조인해 DB에서 집계한다.
- 내 쪽지는 `unreadCount`에서 제외한다.
- 공개 범위·친구 관계·지도 필터를 먼저 적용한 뒤 집계한다.
- 조회만으로 읽음 기록을 만들지 않는다.

## 3. 고정 태그

고정 태그는 API와 DB에서 안정적인 코드로 저장하고 화면 문구·이모지는 프론트가 매핑한다.

| 코드 | 표시 |
| --- | --- |
| `RESTAURANT` | 🍽 맛집 |
| `CAFE` | ☕ 카페 |
| `MEMORY` | 📷 추억 |
| `WORRY` | 💭 고민 |
| `TOUCHED` | 🥹 감동 |
| `DAILY` | 🌿 일상 |

- `notes.tag`와 `NoteTag`를 추가한다.
- 신규 회원 쪽지 작성에는 태그 하나를 필수로 받는다.
- 기존 쪽지는 임의 태그로 왜곡하지 않고 `NULL`을 허용하며, 태그를 선택하지 않은 전체 공개 지도에는 포함하고 태그 필터에는 포함하지 않는다.
- 공개 지도의 `GET /api/v1/notes`와 `/clusters`에 복수 `tags` 조건을 추가하고 선택 태그 중 하나와 일치하는 OR 조건으로 조회한다.
- 친구 지도에는 태그 필터를 사용하지 않는다. `FRIENDS` 요청에 `tags`를 보낸 경우 `400 INVALID_REQUEST`로 명확히 거절한다.

## 4. 지도 보관함

기존 `MINE/SAVED` 필터는 화면 bounds 안의 쪽지만 페이지로 반환한다. 3차의 “쪽지가 한 화면에 다 들어오게 맞추기”를 안정적으로 지원하려면 전체 위치 범위를 먼저 알아야 한다.

전용 요약 API 또는 기존 API 확장 중 하나를 구현 이슈에서 확정한다. 권장 계약은 다음과 같다.

```text
GET /api/v1/users/me/archive/map?type=WRITTEN|SAVED&cursor=...&size=100
```

첫 응답에 `totalCount`, 전체 `min/max latitude/longitude`, 최소 위치 필드를 포함하고 마커는 커서로 이어서 조회한다. `WRITTEN`은 모든 공개 범위의 내 쪽지, `SAVED`는 현재 접근 가능한 저장 쪽지만 포함한다. 두 유형 모두 상세 열람에서 거리 예외를 적용한다.

## 5. 보관함 달력과 목록

현재 API로 3차 요구를 지원한다.

- 달력은 쪽지 원본 `createdAt`을 `Asia/Seoul` 날짜로 변환한다.
- `ALL/WRITTEN/SAVED` 필터와 작성 공개 범위·저장 작성자 분류를 지원한다.
- 날짜 미선택 월 목록은 달력 응답의 기록 날짜를 최신순으로 순회하여 날짜별 목록을 조회하는 현재 프론트 방식을 유지한다.
- 저장한 남의 쪽지는 `isSaved=true`, 내가 쓴 쪽지는 `authorCategory=MINE`과 `isSaved=false`로 구분한다.
- 본인 및 현재 접근 가능한 저장 쪽지는 위치 없이 상세를 연다.

## 6. 저장 취소와 쪽지 삭제

저장과 저장 취소 API는 구현 완료다. 취소 확인 팝업은 프론트에서 표시하고 확인 시 기존 `DELETE bookmarks`를 호출한다.

내 쪽지 삭제는 다음 경로로 구현했다.

```text
DELETE /api/v1/notes/{noteId}
```

- 인증된 작성자만 삭제한다. 존재하지 않거나 타인의 쪽지는 모두 `404 RESOURCE_NOT_FOUND`로 처리한다.
- 한 트랜잭션에서 원본을 삭제한다.
- `note_bookmarks`, `note_discoveries`는 외래 키 연쇄 삭제를 유지하고 실제 PostgreSQL 통합 테스트로 확인한다.
- 삭제 후 작성자 보관함·지도·달력·클러스터·친구 소식과 모든 사용자의 저장 목록에서 조회되지 않아야 한다.

## 7. 상세 이동과 친구 소식

상세의 이동 대상을 분류하는 데 필요한 `noteId`, `isMine`, `isSaved`, `visibility`, `createdAt`은 현재 상세 응답에 있다. 3차 안내대로 이 분류를 위한 신규 백엔드 API는 만들지 않는다. 화면 이동·강조·원래 화면 상태 복원은 프론트가 담당하고, 상세 열람 권한은 기존 API가 계속 검사한다.

친구 소식에는 현재 `noteId`는 있지만 좌표가 없다. 친구 지도로 바로 이동하려면 현재 친구가 작성한 `FRIENDS` 쪽지에 한해 `latitude/longitude`를 추가한다. 소식 조회는 읽음 기록이나 거리 예외를 만들지 않으며, 상세 열람 시 현재 위치로 150m를 다시 검사한다.
