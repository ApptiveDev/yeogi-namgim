# 공통 UI 모션 가이드

이 문서는 [이슈 #142](https://github.com/ApptiveDev/yeogi-namgim/issues/142)의 공통 UI 모션 적용 기준이다. 같은 종류의 UI는 공통 모션을 재사용한다. 바텀시트의 제스처와 전환은 플랫폼의 네이티브 동작을 따른다.

## 모션 기준

| UI | 기본 동작 | 모션 줄이기 사용 시 |
| --- | --- | --- |
| 스낵바 | 화면 아래에서 최종 위치로 올라오며 감속한다(Slide in, Ease out). 닫힐 때는 화면 아래로 내려가며 가속한다(Slide out, Ease in). | 최종 위치에 즉시 표시하고 닫을 때 즉시 제거한다. 메시지와 제공된 동작은 그대로 유지한다. |
| 토스트 | 표시 위치를 고정하고 투명도만 바꾼다(Fade in/out). 메시지 유지 시간과 전환 시간은 별도로 관리한다. | 이동 없이 즉시 표시하고 제거한다. 메시지 유지 시간은 그대로 둔다. |
| 팝업 | 열 때 중심을 기준으로 작은 크기에서 원래 크기까지 확대하며 감속한다(Scale in, Ease out). 닫을 때는 위치를 유지한 채 페이드 아웃한다. | 최종 크기로 즉시 표시하고 닫을 때 즉시 제거한다. |
| 바텀시트 | Expo UI의 네이티브 바텀시트를 사용한다. iOS는 SwiftUI, Android는 Material 3 시트가 드래그 인식, 손을 뗐을 때의 복귀·닫힘, 배경 전환을 처리한다. 모달이 열린 동안에는 뒤 화면의 터치를 막는다. | 시트 전환은 플랫폼 설정을 따르고, 앱에서 추가한 표시 지연과 지도 카메라 이동 애니메이션은 생략한다. |
| 좋아요 | 선택할 때 아이콘에 크기 변화를 한 번 주고 스프링으로 원래 크기에 정착시킨다. 선택 해제나 요청 실패 후에도 최종 크기는 원래 크기다. | 크기를 바꾸지 않고 현재 선택 상태의 아이콘을 즉시 표시한다. |
| 체크박스 | 선택할 때 체크 표시의 획을 순서대로 그린다. 천천히 시작해 중간에 빨라지고 끝에서 감속한다(Ease in out). 선택을 해제하면 그리기를 중단하고 표시를 지운다. | 완성된 체크 표시를 즉시 표시하거나 제거한다. |
| 공통 로딩 스피너 | 처리 중일 때만 일정한 속도로 회전한다(Linear). 성공·실패로 처리가 끝나거나 화면을 벗어나면 회전을 멈춘다. | 회전 대신 정적인 표시나 `불러오는 중`처럼 작업에 맞는 상태 문구를 표시한다. |
| 제목·설명 | 친구·보관함의 빈 화면에서 제목과 설명을 위에서 아래로 한 줄씩 표시한다. 팝업과 바텀시트의 문구는 창과 함께 한 번에 표시한다. | 줄 간 지연 없이 모든 텍스트를 즉시 표시한다. |

## 적용 원칙

- 같은 UI에는 공통 컴포넌트와 [모션 설정](../frontend/src/constants/ui-motion.ts)을 재사용한다. 아래 초기값은 Android·iOS에서 적용 화면을 확인한 뒤 조정한다.
- 열림, 선택, 요청 상태는 화면의 상태에서 결정한다. 연속 탭이나 빠른 열기·닫기로 상태가 바뀌면 진행 중인 모션과 이전 타이머를 취소한다. 이전 완료 콜백이 새 UI를 숨기거나 선택을 되돌리지 않게 하고, 화면을 벗어날 때 남은 지연과 반복 모션을 정리한다.
- 공통 모션은 앱 시작 시 시스템 설정을 읽고, 실행 중에는 `reduceMotionChanged`를 구독한다. Reanimated를 직접 사용하는 기존 동작은 `ReduceMotion.System`을 따른다. [Reanimated 접근성 가이드](https://docs.swmansion.com/react-native-reanimated/docs/guides/accessibility/) · [React Native AccessibilityInfo](https://reactnative.dev/docs/0.86/accessibilityinfo)
- TalkBack·VoiceOver에서 메시지, 체크·선택 여부, 로딩 상태를 모션 없이도 확인할 수 있게 한다. 팝업과 시트는 기존 닫기 동작과 초점 이동을 유지한다.

## 기존 화면에 적용할 때

| 적용 지점 | 확인할 내용 |
| --- | --- |
| [공통 토스트](../frontend/src/components/ui/toast.tsx) | 기존 `showToast` 호출 경로와 화면별 표시 위치를 재사용한다. 현재 메시지는 3초간 유지되며 이 값은 전환 시간이 아니다. 페이드 아웃 중 새 메시지가 오면 새 메시지가 이전 종료 처리로 사라지지 않게 한다. |
| [친구 추가](../frontend/src/components/friends/FriendAddDialog.tsx) · [로그아웃 확인](../frontend/src/components/settings/SettingsSignOutRow.tsx) | 기존 `Modal`의 페이드와 새 팝업 모션이 겹치지 않게 한다. 확인·취소와 Android 뒤로가기의 동작은 유지한다. |
| [주변 쪽지 목록](../frontend/src/components/notes/NearbyNotesSheet.tsx) | [#138](https://github.com/ApptiveDev/yeogi-namgim/issues/138)의 지도 선택·카메라 전환에 맞춰 모달 시트를 표시한다. 아래로 밀거나 손잡이를 눌러 닫는다. Android에서는 시트 바깥 탭과 뒤로가기도 시트를 닫는다. 쪽지 열기를 누르면 시트가 닫힌 뒤 상세를 열고, 뒤로가면 목록과 스크롤 위치를 복원한다. |
| [쪽지 작성](../frontend/src/components/notes/NoteComposeSheet.tsx) | 지도 위 전체 화면 오버레이로 표시한다. |
| 보관함 · 친구 · 마이페이지 | [#141](https://github.com/ApptiveDev/yeogi-namgim/issues/141)의 초기 로딩 스켈레톤은 아직 데이터가 없을 때 콘텐츠 자리를 보여준다. 재진입 시 캐시된 내용이 있으면 계속 보여준다. 새로고침·추가 조회·버튼 요청의 진행을 표시할 때는 해당 작업 위치에 표시를 둔다. |

지도 조회 실패는 하단 탭 위 스낵바에서 재시도할 수 있다. 현재 선택 스프링은 쪽지 저장 성공에 적용한다. 좋아요 버튼과 체크박스는 해당 UI가 추가될 때 적용한다.

## 적용한 초기값

| 모션 | 설정 |
| --- | --- |
| 스낵바 | 진입 220ms, 종료 160ms. 메시지 높이와 하단 여백만큼 이동한다. |
| 토스트 | 페이드 인 160ms, 페이드 아웃 140ms, 메시지 유지 3초. |
| 팝업 | 0.94배에서 원래 크기까지 220ms. 종료는 150ms 페이드 아웃. |
| 주변 쪽지 목록의 지도 카메라 | 시트를 닫으면 카메라 여백을 200ms에 걸쳐 복원한다. |
| 선택 | 1.16배에서 원래 크기로 복귀. 스프링 강성 280, 감쇠 16, 질량 0.65. |
| 로딩 스피너 | 한 바퀴에 800ms. |
| 제목·설명 | 한 줄당 160ms 페이드, 다음 줄은 50ms 뒤에 시작한다. 문구에 지정한 줄바꿈을 기준으로 한다. |

## 적용 후 확인

- [ ] Android·iOS에서 공통 모션의 방향과 순서가 일치한다. 네이티브 시트와 배경은 플랫폼의 전환을 따른다.
- [ ] 주변 쪽지 목록을 스크롤할 수 있고, 시트가 열린 동안 뒤의 지도는 움직이지 않는다. 드래그와 손잡이 탭, Android 바깥 탭과 뒤로가기로 닫으면 카메라 여백이 복원된다. 상세에서 뒤로가면 이전 목록과 스크롤 위치가 복원된다.
- [ ] 연속 탭, 빠른 닫기·다시 열기, 토스트 연속 호출, 요청 성공·실패 후에도 마지막 표시와 선택 상태가 올바르다. 닫힌 UI가 터치나 초점을 가로채지 않는다.
- [ ] 시스템의 모션 줄이기를 켜면 이동·확대·반복 회전·줄 간 지연 없이도 메시지, 조작 버튼, 선택, 로딩 상태를 확인할 수 있다.
- [ ] 보관함·친구·마이페이지의 초기 진입과 재진입에서 스켈레톤과 진행 표시가 화면 상태에 맞게 나타난다.
