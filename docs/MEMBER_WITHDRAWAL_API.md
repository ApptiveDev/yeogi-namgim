# 회원 탈퇴 API

관련 이슈 #103. `DELETE /api/v1/users/me`는 본인의 유효한 회원 Access Token이 필요하다. 성공 응답은 `200 OK`, `Cache-Control: no-store`이며 공통 응답의 `data`는 `{"withdrawn":true}`다. 인증 누락·만료·삭제된 회원은 `401 UNAUTHORIZED`다.

## 처리

한 DB 트랜잭션에서 작성 쪽지의 작성자를 임의 식별자의 비로그인 익명 작성자로 대체한 후 기존 회원 계정·세션·친구 관계 및 초대 관계를 삭제한다. 이메일 인증 기록도 삭제한다. 기존 Access·Refresh Token은 사용할 수 없다. 쪽지 본문·좌표·작성 시각·공개 범위는 유지한다. 익명 작성자의 표시 이름은 `탈퇴한 사용자`다. 실제 쪽지 본문에 포함된 개인 정보는 자동으로 익명화되지 않는다.

관계 삭제 후 전체 공개 쪽지는 기존 거리 제한에 따라 열람할 수 있다. 기존 `FRIENDS` 쪽지는 친구 관계가 없어 더 이상 다른 사용자에게 공개되지 않고, `PRIVATE` 쪽지도 보존되지만 접근할 수 없다. 다른 사람이 저장한 쪽지의 원본은 삭제하지 않는다. 저장·발견 등 후속 테이블과 탈퇴 회원의 데이터 연쇄 삭제는 해당 기능 병합 후 별도로 확인해야 한다.

## Draft 제한

카카오 연결 회원의 연결 해제는 아직 구현하지 않았다. 연결이 존재하면 `409 KAKAO_UNLINK_REQUIRED`로 탈퇴를 거절한다. 카카오 서버 연결 해제·웹훅·실패 복구 정책을 구현하고 실제 연동을 검증하기 전에는 병합·활성화하지 않는다. 작성 쪽지에 개인이 직접 입력한 식별 정보의 처리 정책은 기획과 추가 확인이 필요하다.

프론트는 탈퇴 완료 후 로컬 Access·Refresh Token을 제거하고 로그인 화면으로 이동한다. 탈퇴 확인 UI와 카카오 연동은 별도 작업이다.
